# Naver Style Playbook

## Human Rules

- 네이버 편집기에 바로 옮길 수 있는 읽기 흐름과 서식을 우선한다.
- 초안에 없는 사실, 수치, 날짜, 코드, URL은 추가하지 않는다.

## Current Observed Naver Style

### 제목

- 검색형 안내·실습 초안이라면 핵심 기술이나 대상을 앞에 두고 설정 작업, 설명 범위 또는 독자가 얻을 효용을 뒤에 붙인다. (관찰 8/11건, confidence: high)
- 분석·회고·작업일지라면 핵심 사건이나 프로젝트와 분석 관점, 기록 시점 또는 작업 상태를 결합하되 실제 범위를 과장하지 않는다. (관찰 3/11건, confidence: medium)
- 괄호·대괄호·회차 표시는 환경이나 연재 위치를 실제로 구분할 때만 사용한다. (관찰 3/11건, confidence: low)

### 도입

- 입문·해설형 초안이라면 독자의 의문, 기술의 필요성 또는 기존 방식의 한계를 먼저 제시하고 설명 범위를 안내한다. (관찰 6/11건, confidence: high)
- 설정·작업형 초안이라면 개인적 불편이나 구현 목표를 밝힌 뒤 개요 또는 작업 순서를 짧게 제시한다. (관찰 4/11건, confidence: medium)
- 독자가 이미 맥락을 아는 좁은 작업일지라면 긴 인사말이나 배경 설명 없이 작업 항목부터 시작할 수 있다. (관찰 1/11건, confidence: low)

### 구조

- 항목이 셋 이상이라면 설명형 소제목으로 나누고 각 절에 정의·기능·문제·판단 중 하나만 배정한다. (관찰 9/11건, confidence: high)
- 절차형 초안이라면 준비·설정·변경·확인 순서를 유지하고, 각 단계 안에서 현재 상태·조치·검증 결과를 연결한다. (관찰 5/11건, confidence: medium)
- 개념 비교형이라면 동일한 설명 기준을 반복하고, 회고·분석형이라면 문제·근거·해결 또는 종합 판단이 드러나게 구성한다. 해당 장르에서만 적용한다. (관찰 4/11건, confidence: medium)

### 문단 리듬

- 모바일 게시용 초안이라면 한 문단에 정의·판단·작업 하나만 남기고 소제목과 문단 사이에 충분한 시각적 간격을 둔다. (관찰 10/11건, confidence: high)
- 핵심 용어나 결과는 독립된 짧은 문단으로 분리할 수 있지만, 완결된 문장을 임의의 위치에서 여러 줄로 자르지 않는다. (관찰 7/11건, confidence: high)
- 실습형 글에서는 짧은 작업 설명과 이미지·코드·실행 결과를 교대하고, 필요한 원인 설명은 별도 문단으로 보강한다. (관찰 4/11건, confidence: medium)

### 코드·목록·표

- 단계, 특징, 장단점 등 같은 수준의 항목이 셋 이상이라면 목록으로 전환한다. 순서 의존성이 있으면 번호 목록을, 그렇지 않으면 글머리표를 사용한다. (관찰 8/11건, confidence: high)
- 설정값·명령·로그가 재현에 필요하다면 목적과 주의점을 먼저 설명하고, 뒤에서 핵심 동작과 확인 결과를 해설한다. (관찰 3/11건, confidence: medium)
- 표는 동일한 기준으로 여러 대상을 비교할 때만 사용하고, 모바일에서 관계를 파악하기 어렵다면 목록으로 바꾼다. (관찰 2/11건, confidence: low)
- 긴 콘솔 출력은 성공 여부나 오류 원인을 판단하는 데 필요한 구간만 남긴다. (관찰 1/11건, confidence: low)

### 어조·전환

- 안내·해설형 초안은 명확한 설명체를 기본으로 하고, 입문자에게 필요한 질문형 표현이나 대화형 존댓말만 제한적으로 사용한다. (관찰 8/11건, confidence: high)
- 실습·작업 기록에서는 직접 실행한 조치와 확인된 결과를 구분해 적고, 회고에서는 사실·기술적 원인·개인 평가를 분리한다. (관찰 5/11건, confidence: medium)
- 접속사를 반복하기보다 단계·비교·요약을 알리는 소제목으로 전환한다. 영문 약어와 기술 용어는 최초 한 번 설명한 뒤 표기를 통일한다. (관찰 8/11건, confidence: high)

### 결말

- 안내·실습형 초안이라면 핵심 결과나 판단 기준을 압축하고 독자가 이어서 수행할 행동을 한 가지로 좁힌다. (관찰 6/11건, confidence: medium)
- 트러블슈팅·작업 기록이라면 완료 상태와 적용 전후의 차이를 확인하고, 실제 후속 작업이나 참고 자료가 있을 때만 별도 영역으로 연결한다. (관찰 4/11건, confidence: medium)
- 추천·홍보·협찬 안내는 해당 성격이 명시된 글에서만 본문과 분리해 말미에 한 번 배치한다. (관찰 2/11건, confidence: low)

### 편집 규칙

- Markdown 기호 자체에 의존하지 말고 네이버 편집기의 소제목, 일반 문단, 번호 목록, 글머리표, 표 또는 인용 요소로 변환한다. (직접 서식 관찰 7/11건, confidence: medium)
- 강제 줄바꿈·과도한 빈 줄·보이지 않는 공백을 의미 단위의 문단 간격으로 정규화하고, 반복된 제목과 설명은 한 번만 남긴다. (관찰 10/11건, confidence: high)
- 이미지가 없어도 이해되는 설명을 먼저 쓰고, “위 이미지” 같은 지시어는 실제 배치가 확정된 경우에만 사용한다. (관찰 3/11건, confidence: medium)
- 메뉴, 검색, 카테고리, 공감, 공유, 댓글, 방문 통계, 저작권 안내와 관련 글 문구는 본문에서 제거한다. (관찰 11/11건, confidence: high)
- 코드의 들여쓰기와 경계는 보존하고, 해시태그·참고 링크·고지문은 결론 뒤의 별도 영역에 둔다. (관찰 5/11건, confidence: medium)

### confidence

- 네이버 입력은 11건이다. 핵심 대상이 드러나는 제목, 소제목 중심 구조, 짧은 문단, 목록 활용과 인터페이스 제거는 여러 날짜와 장르에서 반복되어 confidence가 높다.
- 코드·표·이미지·상업적 고지와 장르별 결말은 일부 사례에 한정되므로 조건부 규칙으로만 적용한다.
