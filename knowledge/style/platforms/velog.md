# Velog Style Playbook

## Human Rules

- Markdown의 제목, 목록, 표, 코드 블록, 링크를 의미에 맞게 사용한다.
- 초안에 없는 사실, 수치, 날짜, 코드, URL은 추가하지 않는다.

## Current Observed Velog Style

### 제목

- 개념 정리나 개발자 견해 초안이라면 하나의 핵심 개념·질문·판단 대상을 간결하게 전면화한다. 프로젝트 소개형이라면 프로젝트의 정체성과 중심 문제를 함께 드러낼 수 있다. (관찰 3/3건, confidence: medium)
- 절차보다 주장이나 관점을 앞세우는 방식은 견해형 글에서만 적용하고, 실습·문제 해결형 제목으로 일반화하지 않는다. (관찰 2/3건, confidence: medium)

### 도입

- 핵심 주장, 실제 문제 또는 작성 계기를 초반에 빠르게 제시한다. 독자가 글의 출발점을 알기 어려운 초안에 적용한다. (관찰 3/3건, confidence: medium)
- 자료 정리형 글은 정리 목적과 참고 관점을, 프로젝트·에세이형 글은 역할·사용자 문제·개인적 고민을 밝힌다. 글의 장르에 맞는 한 방식만 선택한다. (관찰 3/3건, confidence: medium)

### 구조

- Markdown 소제목을 논점 단위로 배치하고, 질문이나 대원칙에서 세부 기준·근거·사례로 확장한다. (관찰 3/3건, confidence: medium)
- 프로젝트 소개형은 문제 인식·확인 과정·방향·다음 계획으로, 개념 정리형은 원칙·세부 기준·예시·점검으로 구성할 수 있다. 각 유형에서만 조건부로 적용한다. (각 유형 관찰 1/3건, confidence: low)
- 하위 논점이 많다면 번호 계층을 사용할 수 있지만 헤딩과 번호 체계를 중복해 지나치게 깊게 만들지 않는다. (관찰 1/3건, confidence: low)

### 문단 리듬

- 핵심 문장을 독립시킨 뒤 해설·근거·사례를 이어 붙이고, 논점이 바뀌는 지점에서 문단을 분리한다. (관찰 3/3건, confidence: medium)
- 논설형 초안이라면 질문과 답변, 주장과 반론, 원칙과 예외를 교대해 예상 반문을 처리한다. (관찰 2/3건, confidence: medium)
- 설명 문단은 필요한 만큼 유지하되 짧은 강조 문장만 연속 배치해 논리가 파편화되지 않게 한다. (관찰 2/3건, confidence: medium)

### 코드·목록·표

- 코드 품질이나 설정 차이를 비교하는 초안이라면 변경 전후 코드를 각각 Markdown 코드 블록으로 분리하고 비교 목적과 판단 기준을 설명한다. (관찰 1/3건, confidence: low)
- 단계·체크리스트·판단 기준처럼 병렬 항목이 셋 이상이라면 Markdown 목록으로 정리하되, 목록 뒤에 의미나 결론을 덧붙인다. (관찰 2/3건, confidence: low)
- 코드 블록의 언어 표시는 실제 언어를 확인할 수 있을 때만 넣고, 존재하지 않는 코드나 실행 결과를 만들어 추가하지 않는다. (코드 관찰 1/3건, confidence: low)
- 표는 반복 관찰되지 않았다. 비교 대상과 축이 명확하고 작은 화면에서도 읽을 수 있을 때만 사용한다. (관찰 0/3건, confidence: low)

### 어조·전환

- 개인 경험과 기술 판단을 함께 다룬다면 단정적인 핵심 문장과 경험 범위에 대한 유보를 함께 사용한다. 사실·근거·개인 의견은 구분한다. (관찰 3/3건, confidence: medium)
- 질문형 소제목이나 질문 문장을 사용했다면 바로 이어지는 문단에서 근거와 작성자의 답을 제시한다. (관찰 2/3건, confidence: medium)
- 문제 제기에서 해결 방향으로 이동할 때는 조사·검증·반론 검토 등 실제 전환 근거를 명시한다. (관찰 2/3건, confidence: medium)

### 결말

- 본문의 중심 질문에 대한 최종 답이나 현재의 판단을 남긴다. 새로운 논점이나 근거를 결말에서 추가하지 않는다. (관찰 2/3건, confidence: medium)
- 개념 정리형은 요약·점검 항목·참고 자료로, 프로젝트·에세이형은 달라진 관점과 실제 다음 방향으로 마무리할 수 있다. 유형별 단일 관찰이므로 선택적으로 적용한다. (각 유형 관찰 1/3건, confidence: low)

### 편집 규칙

- Markdown 헤딩 깊이를 일관되게 유지하고, 각 소제목의 첫 문단이 해당 질문이나 주장을 바로 이어받게 한다. (관찰 3/3건, confidence: medium)
- 코드·설정값·출력은 코드 블록이나 인라인 코드로 일반 문단과 구분하고, 예제마다 목적과 해석을 붙인다. (관찰 1/3건, confidence: low)
- 링크는 관련 주장 가까이에 설명적인 문구로 배치하고, 참고 링크 묶음은 본문 결론과 분리한다. 링크만으로 논지를 대신하지 않는다. (관찰 2/3건, confidence: medium)
- 표가 작은 화면에서 읽기 어렵다면 목록으로 바꾸고, 태그는 본문 설명을 대신하지 않는 보조 메타데이터로 취급한다. (관찰 1/3건, confidence: low)
- 태그, 팔로우, 프로필, 이전 글, 댓글 등 플랫폼 인터페이스는 제거하되 작성자가 의도한 참고 링크와 역할 정보는 보존한다. (관찰 3/3건, confidence: high)

### confidence

- Velog 입력은 3건이며 프로젝트 소개, 기술 정리, 개발자 에세이처럼 장르가 서로 다르다. 소제목 중심 구조와 핵심 논점 전개는 반복됐지만 표본이 작아 종합 confidence는 medium이다.
- 코드 비교, 번호 계층, 표, 체크리스트와 유형별 결말은 단일 사례이거나 관찰되지 않았으므로 confidence를 low로 제한한다. 네이버 관찰이나 일반적인 Markdown 관행을 Velog의 고정 형식으로 추정하지 않는다.
