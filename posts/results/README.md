# 게시 결과 기록

`drafts`는 작성 중인 원고, `final`은 업로드 가능한 최종 원고, `results`는 외부 플랫폼에 실제로 게시됐는지 확인한 결과를 보관한다.

원고가 완성됐거나 Velog 편집기에 임시 저장됐다는 사실만으로는 `published`로 기록하지 않는다. 아래 증거를 모두 확보한 뒤 게시 완료로 바꾼다.

- 플랫폼과 계정
- 게시 제목
- 최종 원고 경로와 SHA-256
- 게시 시각과 시간대
- canonical URL
- 로그아웃 상태에서 본문이 열리는지 여부
- 공개 프로필의 글 수와 목록 노출 여부
- 프로필 이미지가 있다면 공개 페이지와 CDN에서 정상 표시되는지 여부

## 상태

- `prepared`: 최종 원고와 게시 설정이 준비됐지만 최종 게시를 확인하지 않음
- `published`: 플랫폼이 canonical URL을 발급함
- `verified`: 로그아웃 상태의 공개 URL과 프로필 목록에서 게시물을 확인함
- `missing`: 과거 `verified` 기록이 있으나 공개 페이지에서 찾을 수 없음

## 게시 직후 절차

1. canonical URL과 게시 시각을 즉시 기록한다.
2. 로그아웃 또는 시크릿 창에서 URL을 연다.
3. 제목, 본문 시작·끝, 코드 블록, 표, 링크를 확인한다.
4. 공개 프로필에서 글 수와 두 게시물의 노출을 확인한다.
5. 프로필 이미지의 실제 URL과 정상 로드 여부를 확인한다.
6. 10분 뒤와 다음 날 같은 항목을 다시 확인한다.
7. 결과 파일을 커밋해 외부 상태와 원고의 연결 근거를 남긴다.

문제가 재발하면 결과 파일의 canonical URL, 마지막 정상 확인 시각, 원고 SHA-256을 먼저 대조한다. 확인되지 않은 삭제 원인은 단정하지 않는다.
